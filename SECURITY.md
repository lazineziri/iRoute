# Security policy

Do not report vulnerabilities through public issues. Until a dedicated security mailbox is published, use a private repository security advisory.

Supported versions will be listed after the first public release. The project does not collect prompts, outputs, credentials, or telemetry by default. External side effects must be classified, authorized, idempotent, and auditable.

Never commit model keys, connector credentials, personal data, production traces, or unredacted evaluation fixtures.
