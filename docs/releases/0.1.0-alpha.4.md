# iRoute 0.1.0-alpha.4

Release date: 2026-10-01. Registry publication is confirmed only when the
verified-tag release workflow succeeds.

## Summary

This release establishes the .NET-only repository and package boundary. iRoute
now has five production projects, one test project, one executable composition
root, one CLI/tool package, and one multi-mode OCI image.

## Highlights

- Consolidated all public DTOs, interfaces, ports, options, and shared
  primitives in `iRoute.Common`.
- Moved routing, policies, execution behavior, gateways, capabilities, and
  validation into `iRoute.Services`.
- Consolidated Entity Framework Core, SQLite/PostgreSQL stores, entities, and
  migrations in `iRoute.Data`.
- Reduced `iRoute.Core` to a stable execution facade and made `iRoute.Runtime`
  the only executable/composition root for API, worker, migration, and client
  modes.
- Added architecture tests that enforce the allowed project dependency graph
  and the single-contract-assembly rule.
- Removed the multi-language SDK source trees and their package/deployment
  workflows from this repository.
- Replaced the three runtime container variants with one non-root image whose
  command selects `serve`, `worker`, or `migrate`.
- Rebuilt CI around format, build, test, package/tool installation, Compose,
  container commands, SQLite/PostgreSQL migrations, API health, OpenAPI,
  dashboard, asynchronous execution, SSE, idempotency, and tenant isolation.
- Replaced separate release/publish workflows with one verified-tag workflow
  for NuGet, GHCR, provenance/SBOM, checksums, source archive, and GitHub release.
- Updated all current documentation for the .NET-only architecture.
- Split execution orchestration into focused service classes; cancellation and
  reconciliation business decisions no longer live in HTTP endpoints.
- Denied self-approval and revalidated previously approved actions against the
  independent-actor policy.
- Added native OpenAI/Anthropic structured-output API adapters, local Claude CLI
  subscription access, and explicit unknown-cost semantics. ChatGPT supports
  local macOS/Linux dynamic sign-in, account selection, refresh, revocation, and
  bounded Responses streaming. One local account's sign-in/model access was
  verified diagnostically; four ChatGPT models and the Claude CLI adapter now have
  exploratory live pipeline verification, not production quality certification.
- Added version-aware memory/context selection, decoded Unicode relevance,
  persisted artifact confidence, and consistent task/provider token budgets.
- Added experimental durable tenant quotas, fair queued dispatch, PostgreSQL
  contention/migration tests in CI, and native HTTP body/rate limits.
- Added execution, approval, cancellation, reconciliation, provider, subscription,
  and gateway-contract regression tests.
- Redacted credential-bearing gateway configuration in diagnostic strings and
  included PostgreSQL contention/migration tests in release verification.

## Release verification

Local preflight passed formatting and analyzers, 229 tests (four opted-in live
tests skipped), all five package builds, an isolated tool installation, and the
actual SQLite/PostgreSQL container smoke action. Source and Git-history scans
found no credentials. No new live model calls were made during release preflight.
Hosted CI, CodeQL, secret scanning, and the manual release dry run must still
succeed on the exact release commit before tagging.

## Packages

The release workflow produces these NuGet artifacts:

- `iRoute.Common`
- `iRoute.Services`
- `iRoute.Data`
- `iRoute.Core`
- `iRoute` as a .NET tool

It also publishes `ghcr.io/lazineziri/iroute:0.1.0-alpha.4` for Linux AMD64 and
ARM64. The image defaults to `serve`; use `worker` or `migrate ...` for the
other process modes.

## Breaking changes

- Removed standalone Node.js, Python, Java, PHP, Rust, and old .NET SDK project
  layouts from this repository.
- Removed the previous `Contracts`, `Application`, `Infrastructure`, `Hosts`,
  and `Clients` wrapper directories.
- Container consumers must move from component-specific images to the unified
  `ghcr.io/lazineziri/iroute` image and supply the process command where needed.
- Production package IDs now follow the five-project structure above.
- Custom `IExecutionService` implementations must expose cancellation and action
  reconciliation commands; `ITaskPolicyEngine.EvaluateApproval` now receives the
  approver actor ID. Approval/action exceptions moved from Services to Common.
- API consumers must treat `usage.costKnown=false` as unknown cost, not free
  execution. The optional field defaults to true for older gateway envelopes.
- `IExecutionStore.TryRequestCancellationAsync` now returns true only for a newly
  persisted request; repeated requests return false without changing the timestamp.

## Upgrade notes

Treat this as a source and packaging boundary change. Update project references,
NuGet references, container names, and deployment commands together. Run
`iroute migrate status` and `iroute migrate up` before starting the new API and
workers. Preserve the database and apply the normal additive-schema rollback
procedure if application rollback is required.

## Known limits

This remains an alpha. Quota/fairness foundations have experimental coverage,
not production-scale guarantees. Quota operations, production connectors,
distributed action reconciliation hardening, sustained load/soak testing,
production failover validation, and a security-response SLA remain future work.
