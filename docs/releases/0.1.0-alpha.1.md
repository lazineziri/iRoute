# iRoute 0.1.0-alpha.1

- Release date: 2026-08-01
- Channel: alpha prerelease
- Public API: v1

This is the first adoption-ready source release of the task-aware iRoute runtime.
It completes workstreams W01-W16 with a credential-free deterministic quick
start and production-shaped PostgreSQL/Kubernetes references.

## Highlights

- Resolve trusted project state and deterministic work before invoking a model.
- Compile bounded, provenance-bearing context instead of forwarding full history.
- Route against measured quality, cost, latency, token, capability, and policy
  constraints with explainable decisions.
- Persist workflows, approvals, external-action reservations, artifacts, memory,
  dependency edges, lifecycle archives, events, and observability.
- Integrate providers only through generic model-gateway and normalized
  capability boundaries.
- Operate with schema-aware readiness, explicit migrations, non-root containers,
  and horizontally scaled API replicas.
- Use six protocol-only SDKs and the `iroute` CLI against the same v1 contract.

## Install

Follow [the clean installation guide](../installation.md). The smallest path is:

```bash
docker compose --file deploy/compose.sqlite.yaml up --build --wait
curl --fail http://localhost:8080/health/ready
```

## Compatibility and security

This is an alpha prerelease. The published v1 wire contract remains additive as
defined in [the compatibility promise](../compatibility.md). Only the latest
tagged prerelease receives best-effort security fixes. Report vulnerabilities
through a private repository security advisory as described in
[SECURITY.md](../../SECURITY.md).

## Known limits

- In-flight execution and cancellation are process-local.
- The lifecycle worker must remain one replica per database until distributed
  leasing exists.
- Production identity, PostgreSQL, backups, ingress/TLS, external model gateway,
  secrets, and real connector adapters are operator responsibilities.
- SDK registry publication is not implied by this source release.

## Upgrade and rollback

This is the first tagged prerelease. Existing source deployments should back up
PostgreSQL, run the release migration image `status` and `up` commands, then roll
API replicas and finally replace the single worker. Prefer application rollback
while retaining the additive schema. Follow [operations.md](../operations.md)
before any confirmed schema downgrade.

## Integrity

The GitHub release includes `release-manifest.json` and `SHA256SUMS`. Verify every
download before use. Container images built by downstream operators must be
pinned by immutable version and, for production, digest.
