# Initial product benchmark — 1 October 2026

Result: the current iRoute pipeline substantially reduced provider input tokens
on deliberately redundant history/context and avoided inference on exact warm
reuse. Small requests barely improved. Factual assertions passed, but this is
not broad quality or production evidence, and cold latency did not improve.

## Scope and accounting

- Local macOS arm64, .NET 10, unpublished `0.1.0-alpha.4` working tree based on
  `d04b495`. These results are not measurements of a released package.
- Native iRoute ChatGPT subscription access with low reasoning. No Astra,
  API-key billing fallback, Claude, tools, or external writes.
- Four explicitly selected models, seven cold cases plus a new warm request
  and a changed-source request per model: 36 pairs, 72 successful executions,
  68 actual inference HTTP calls.
- Baseline: complete original JSON input through the same unmodified native
  adapter, model, instructions, and output schema. Optimized: full execution
  pipeline including routing, context compilation, SQLite, validation, and reuse.
- One sample per pair; cold order alternates. Each model has its own fresh database
  and each cold case its own project. The warm result's cold creation is included.
- Token counts are provider-reported. Input includes cached tokens and output
  includes reasoning. Neither is subtracted or added again. Provider-cached
  input counts were zero in these model-call observations. Monetary cost is unknown.

The paired cohort completed between `2026-09-30T22:27:17Z` and
`2026-09-30T22:31:39Z`, which is 1 October in Europe/Tirane. Exact observations,
outputs, errors, and context manifests remain in the raw reports below.

| Model | Direct input + output tokens | iRoute input + output tokens | Reduction | Paired fact checks | Direct / iRoute inference calls |
|---|---:|---:|---:|---:|---:|
| gpt-5.6-sol | 4,167 | 1,809 | 56.6% | 9/9 | 9 / 8 |
| gpt-5.6-terra | 4,154 | 1,792 | 56.9% | 9/9 | 9 / 8 |
| gpt-5.6-luna | 4,487 | 1,938 | 56.8% | 9/9 | 9 / 8 |
| gpt-5.5 | 4,161 | 1,801 | 56.7% | 9/9 | 9 / 8 |
| Total | 16,969 | 7,340 | 56.7% | 36/36 | 36 / 32 |

Across all nine cases per model, input tokens alone fell from 3,755 to 1,447:
61.5% less input. Across all four models that is 15,020 to 5,788. On the seven
cold cases alone, input fell from 3,421 to 1,284 per model (62.5%); across the
four models, total input plus output fell from 15,159 to 6,475 (57.3%). These
figures describe this workload, not an expected customer-average reduction.

## Where input reduction came from

Provider input counts were identical across the four models for each case.

| Case | Direct input tokens per model | iRoute input tokens per model | Reduction |
|---|---:|---:|---:|
| Short summary | 170 | 169 | 0.6% |
| Short email draft | 150 | 149 | 0.7% |
| Long irrelevant history | 1,738 | 252 | 85.5% |
| Sixteen duplicate facts | 420 | 149 | 64.5% |
| Superseded facts | 201 | 149 | 25.9% |
| Albanian input, English summary | 200 | 199 | 0.5% |
| Relevant code in older history | 542 | 217 | 60.0% |
| New warm request | 170 | 0 | 100%; no inference |
| Changed-source request | 164 | 163 | 0.6%; fresh inference |

The critical-history case retained the approval code `AX-417`, not just the
latest history items. Changed-source output retained Tuesday at 14:00 and did
not contain the previous Friday at 10:00. All four warm executions used
`ExactArtifact` with a new execution/idempotency key and zero observed inference
calls. Short-case total-token differences largely reflect output/reasoning
variation rather than meaningful context compression.

|---|---:|---:|---|
| Seven cold cases per model | 90,690 ms | 93,534 ms | iRoute 3.1% slower in aggregate |
| Complete nine-case workload | 122,660 ms | 109,378 ms | iRoute 10.8% lower; includes warm reuse |
| Warm request, per model | 2,762–4,919 ms | 26–35 ms | Local reuse avoided inference |

Timings include local orchestration and are sequential single observations.
They do not establish p95/p99 performance, significance, steady-state throughput,
or a generally faster model path. Fewer input tokens did not reliably make these
small completions faster.

## Bugs fixed and follow-up

Local regressions reproduced incompatible artifact reuse when output limits
changed. The result fingerprint now includes output-affecting policy and
metadata; submission fingerprints also prevent constraint changes under the
same idempotency key. Valid no-model budgets can still reuse a compatible result.

Usage normalization now preserves optional cached-input and reasoning details,
validates them against the corresponding total, and does not double-count them.
Workflow aggregation leaves partially known details unknown.

After the paired cohort, seven additional local regressions reproduced a project
state bug: excluded inactive/expired/superseded sources could overwrite current
memory, and explicit expiry was lost. The fix shares the compiler's lifecycle
guard with materialization and preserves source expiry.

A separate live follow-up on the final corrected pipeline deliberately placed
the inactive source **after** the current source. All four models produced the
current meeting facts (one inference call each), followed by four successful
`StructuredState` fact lookups with zero inference calls. These eight executions
and four calls are excluded from the paired savings totals above; total live
inference across the cohort and follow-up was 72 calls.

The final offline suite passed 168 tests, with two explicitly opt-in live tests
skipped and no failures. Release build passed with zero warnings/errors,
formatting and whitespace checks passed, and all five local NuGet packages built.
A fresh installation of the packaged CLI passed runtime/auth help checks.
Packages remain unpublished. Existing
persisted stale memories are not automatically repaired; see the
[upgrade note](../product-benchmark.md#upgrade-note).

## Quality limits and product interpretation

Fact checks verify required project/day/time/code strings and prohibit named
stale facts. Both paths passed those checks in all 36 pairs. Outputs are retained
for inspection, but a passing check does not prove that every assertion is
supported, that confidence is calibrated, or that writing quality is equivalent.
For example, some draft outputs include polite attendance/awareness language
not explicitly supplied in the facts. This check does not score that language.

The Albanian example is one translation/control case, not multilingual ranking
validation. Model identities were pinned, so cheaper-model selection, routing
quality, escalation, and synthetic-profile accuracy were not evaluated. Context
budgets still use approximate byte-based estimates, not exact provider token
counts. No production measured profiles or monetary savings were declared.

The product has useful evidence for redundancy removal, retained key facts,
safe fresh work, and exact/typed no-model reuse. Before beta it still needs
larger/repeated realistic datasets, independent semantic scoring, adversarial
context cases, tenant quotas/fairness, and sustained load/security validation.
The performance-testing workflow influenced this work by separating cold from
warm costs, measuring actual usage, and refusing to infer latency gains from
token reductions alone.
